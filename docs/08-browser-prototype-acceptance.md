### G：扩展边界检查（本轮必查，不要求实现远期功能）

- **G01：**状态模型与规则中，州 ID 仅表达地理划分，不暗含全州唯一统治者、生态类型或天然屏障。地点有稳定标识，可以由未来组织引用，不需现在创建空宗门系统。
- **G02：**世界事实、参数和干预事件为结构化数据，界面说明可由事实生成；展示文字不能直接改状态。后台状态可独立于界面运行。没有 AI 依赖，不要求现在构建 RAG。
- **G03：**加工来源、载体／库存位置与能力分开表达；未来增加属性无需把“灵气总量”重解释为某种元素。只检查职责与数据边界，不提前做无用属性引擎。

G 通过需引用实际代码／状态格式，不能仅引用这份设计文档。当前逐项状态与证据见 10 验收进度。

## 1. 交付目标与范围

交付本地运行、浏览器打开的二维生态沙盘。用户可以生成地图、观察数百年变化、逐格查看原因、暂停修改并继续实验。

首版必须包含：一个州及周边的连续方格地图、关联地理生成、未分属性的灵气、普通草树与灵草灵树、种群更替、稀有古树、种子扩散与存留、灵矿、植物改变地表小环境、图层与收支、全部已选编辑能力。

动物、修仙法门、宗门政治、人物 RPG 和 AI 叙事不在首版范围内。不能因历史文档出现这些模块而加入首版依赖。也不以固定剧情或每张地图强制出现所有参考形态作为验收目标。

### 尺度状态

256×256（65,536 格）作为建议的标准压力规模；128×128 可用于快速调试，不能仅用小地图结果宣称标准规模通过。此前每格 100 米、主州面积比例、3～4 个邻州边缘均未被用户确认。

首版界面在物理尺度确定前显示格坐标与格数，不把 25.6 公里大小的区域宣称为已确定的完整大州。模拟参数使用明确的格单位、时间单位，不能混用米与格。主州与周边的产品范围保持，实际公里尺度是待落实配置，不另造隔离小世界。

## 2. 总体设计

| 模块 | 职责 | 必须隔离的依赖 |
| --- | --- | --- |
| 配置与世界生成 | 种子、地形岩性气候地热、初始库存和种群；直接生成／预运行 | 不按“灵谷”等场景名强制修改未来结果 |
| 模拟内核 | 输入、加工、传导、吸收释放、结合、种群、种子、古树、小环境 | 不依赖画面帧率、相机或 HTML 元素 |
| 数据与记录 | 世界状态、随机状态、收支、事件、配置版本、干预记录 | 不从渲染颜色反推模拟数据 |
| 地图呈现 | 连续地形与美术、方格选择、图层、图例 | 地图图形不充当模拟实体的唯一存储 |
| 检查与编辑 | 逐格信息、收支解释、修改预览和提交 | 命令经模拟边界统一生效，不半步改写 |
| 存档与验证 | 导入导出、继续运行、批量对照和数值审计 | 不需在线 AI 或远程服务才可验证 |

建议后台运行模拟，主界面接收状态快照；具体绘图库和线程组织在实现时决定。当前选择的是浏览器交付路线，不是把每格做成一个网页元素。

## 3. 判定方式与证据

- **R：规则硬门槛。**任何一项失败，不能宣布模拟正确。
- **S：场景验收。**全部 11 类参考情境分别验证；每类使用合适且公开的初始条件及反事实对照。
- **U：用户体验门槛。**实际在浏览器操作，不以截图或单元测试代替。
- **P：性能与可靠性。**在登记的设备、浏览器及标准规模测量。

所有验收条目初始状态为“未执行”。允许通过／失败／未执行／无法判定四种状态；“看起来合理”不能替代证据。失败需记录复现条件与影响，不静默降低标准。

## 4. R：规则验收

| ID | 必须成立 | 验证方法与通过条件 |
| --- | --- | --- |
| R01 | 来源与总账一致 | 记录每步期初、外部输入输出、人工增减及期末；内部转移成对抵消，检查各池与全域误差 |
| R02 | 库存和能力有界 | 不出现 NaN、Infinity、实质负库存；多邻居／多植物同时请求不能透支同一源；容量增加不自动充满 |
| R03 | 来源能力独立 | 普通植物天道加工为零；灵植加工、地下吸收、地表吸收、释放连续数值独立；单强、双强、零加工而高地道吸收均能运行 |
| R04 | 不强加未定损耗 | 不以无说明的“消耗”平衡总量；溢出、失败转化和容量缩减有明示去向，任何新增去向先写参数与规则说明 |
| R05 | 地理连续 | 同一状态只改州界标签后，灵气与植物演化不变；通道改变才影响传导。模拟外边缘的封闭／开放条件需显示并记账，不能伪装成州界 |
| R06 | 地理关联有因 | 温度可追溯背景、海拔、坡向和地热；水分有生成依据；灵气产能与储量分开，地热不是任意“地表富集”标签 |
| R07 | 无生命也运行 | 清除植物后地质输入、储存、流动、释放和矿物过程继续，符合来源与容量约束 |
| R08 | 一树种一草种 | 每格最多一个已建立树种和草种；种子库可有候选种但不算已建立群落；新种仅在旧种衰退且足够低后建立 |
| R09 | 种群更替 | 株数为非负整数、变化可解释；有利条件下可通过生死繁殖持续存在，不整格同步寿终、不自动补满；长期均衡数量响应环境与竞争 |
| R10 | 种子与局部灭绝 | 新格建立有初始或邻格种源，受萌发条件限制；种子有寿命；无种子、无邻近种源且无编辑时不凭空长出；普通植物不自动变灵植 |
| R11 | 特性实际参与 | 温度水分光照耐受、体型遮阴、生长繁殖寿命、灵气需求耐受与各能力都影响对应过程；单因素对照验证，不能只有字段和说明 |
| R12 | 古树正确计量 | 初始／手动及自然成长可产生古树；计入该格唯一树种与总数；从种群拆出时年龄、生物量及库存不重复；年龄本身不凭空增加灵气或赋予能力 |
| R13 | 生死分账 | 寿终或致命损伤终结先天一气，不转成可采集库存；后天积累进遗骸并逐步分解；有限种子和先天输入另记 |
| R14 | 矿物形成有过程 | 岩性、可用量及持续条件实际参与，形成矿物结合量从源扣除；不因贴灵矿图标增加资源 |
| R15 | 局部环境反馈 | 背景固定，实际温度水分光照可随植被逐渐改变，影响后续生长；保湿受供水限制，遮阴不消除地下地热；植物消失后反馈按状态变化而非瞬间重置 |
| R16 | 重现与独立时钟 | 同版本、配置、种子、编辑及步数在同环境得到相同状态；暂停无漂移；加速改变步数吞吐而非生态公式；切图层、移动镜头不改变结果 |

### 从 01／02 补充的专项硬门槛

- **R17 世界不依赖观察：**同种子、参数、操作和步数，比较全图观察、只看角落、关闭绘制的结果；所有格子的状态与随机进程一致。后台标签页可能受浏览器调度限速，因此按相同步数比较，不承诺后台相同墙钟速度。镜头移到远方不能首次生成植物或补算另一套历史。
- **R18 因果与干预记录：**死亡、种群建立／替换、矿化起始和人工操作至少记录时间、稳定位置／对象、事件类型、相关前后值与实际触发条件。收支只说明本步直接原因，不能冒充完整历史；历史原因查询缺证据时明确显示未知。对照实验显示两个分支的差异，不把关联自动称为唯一因果。
- **R19 完整生命与分账：**普通和灵性植物都具有先天生命记录（可按年龄组表达），出生输入有据；落叶、分解或其他部位脱离不产生额外先天输入，也不复制整株后天库存。新种群建立按种源及生命定义赋予先天一气；不能把预留功能中的活体夺取默认为存在。普通植物不能仅因处于富集地就自动获得天道加工能力。
- **R20 限速与留存：**对单地块独立改变接收、加工、容量、传导和释放参数，检查影响作用在对应环节；饱和时不超容、不丢失未说明的溢出。跨多个载体的循环不增加外部输入，活体释放不要求等到死亡；库存、产率、游离浓度在数据与界面均有不同字段和单位。

工程误差建议：每步各池及全域账差不超过 1e-8 × max(1, 期初绝对库存与本步绝对收支之和)。若精度选型需调整，必须在验收前登记，不能看到失败后临时放宽；同时报告 500 年累计绝对账差，避免每步小误差累积被忽略。

同层换种如何处理残存旧株、种子后天库存、古树阈值、局部温湿度函数、外边界条件，须在实现前形成明确的参数和规则表。可采用合理的可调实现选择，但不得悄悄突破已定世界规则。

## 5. S：11 个参考情境的验收矩阵

每个实验提供：生成种子、配置版本、初始状态、位置、观察区、时间范围、对照、指标和结果文件。阈值与观察窗口必须在正式验收前固定；不能看见结果后才挑位置与时间。比较在相同背景条件与等长时间下进行。

| ID | 情境及初始条件 | 需要观察到的证据 | 必须的对照 |
| --- | --- | --- | --- |
| S01 | 山谷聚灵：适配谷地、有种源、地下供给与释放 | 地下到地表有正转移，种子萌发有来源、种群随适宜性增长 | 削弱释放，比较可用量与建立过程 |
| S02 | 荒地藏灵：适合蓄积与矿化岩层、弱释放、地表不适配 | 地下／矿物库存富集，地表植物仍稀少；不能仅以“荒地”标签触发矿化 | 不适合矿化的岩性或移除供给，其他相同 |
| S03 | 灵泉养地：有来源且与地表出口连接的地下通道 | 泉边输入可追溯上游扣减，影响局部可用量与生长 | 断开通道，不能保留无源固定产量 |
| S04 | 一山两面：匹配岩性和供给，不同坡向 | 光照／实际温度有差异，适配物种群落出现对应差异 | 交换坡向或光照条件，检查因果响应 |
| S05 | 源断地衰：依赖输送且已建立的灵地 | 关闭通道后流入下降，库存及种群依实际缓冲逐渐响应 | 同存档不关闭通道；记录人工操作时点 |
| S06 | 一树成地：弱地质供给、高效加工灵树、有可用周边种源 | 树的天道输入与释放可核对，周边可用量／生长相较对照改善 | 保留相同初始树库存，把加工能力设零，排除仅消耗初始存量 |
| S07 | 群草养地：单株弱加工但群体可生存 | 单株与成片的总加工释放差异能解释当地变化 | 相同区域低密度或零加工群体，不要求密度无限增益 |
| S08 | 古林藏灵：适合长期留存和循环的林地 | 生物与遗留物／土壤结合库存高，游离部分占比低，账可分解 | 减少留存能力，比较相同外部输入下的库存分布 |
| S09 | 强植争灵：环境供给有限、强吸收低释放植物与邻近灵草 | 强植吸收账增加，邻草可用量与生长受压 | 保持体型遮阴及其他参数，仅降低吸收能力，区分遮阴影响 |
| S10 | 树落草兴：古树有后天积累、附近有适配草种 | 死亡到遗骸到环境的释放链、时间滞后、草增长可追溯 | 比较零遗骸分解实验以区分遮阴解除；零分解时库存保留在遗骸，不删除 |
| S11 | 恶地育古树：恶劣地热环境、强地下产灵、适配植物、有水分背景及后续种源 | 天道加工设零仍可从地道供给成长；古树降低局部不利程度后其他植物得以建立；地下来源仍在 | 非适配植物不能同样成长；关闭地下取用则成长受限；关闭小环境反馈则相应温湿度改善不出现 |

所有场景都必须运行同一内核。场景预设只能改变初始数据和公开编辑命令；不得在第 N 年注入结局。除了受控实验，至少选 5 个预先登记的普通随机种子各运行 500 年，报告全部结果及差异，不筛去“不漂亮”的结果；不要求所有随机世界都繁盛、稳定或包含全部 11 形态。

## 6. U：用户体验验收

| U02 | 看全图与放大 | 地图具有山脊／坡面、岸线、岩土纹理、草树轮廓与疏密、古树体量；不仅靠颜色区分；图形来自当前状态 |

## 7. 用户评估路线（约 20～30 分钟，建议）

1. 用普通种子生成地图；在全图与放大视角辨认山川、林草和古树。
2. 找一处“地下多、地表少”的格子，切图层并解释它；检查图例与单位。
3. 加速推进，观察若干位置而非盯单一格；暂停检查收支，回答“什么变了，主要因为什么”。
4. 从公开的 S06 初始存档运行一树成地；查看过程，记录是否能直观看到片区变化，而非仅看数值增长。
5. 用 S11 检查零天道加工的适配植物能否依靠地下供给成长，及实际地表温湿度如何改变。
6. 修改通道并继续；随后另用 S10 使古树死亡，检查缓慢衰退／分解后的生长，不预设两次变化都立即发生。
7. 保存并重载，继续推进；确认位置、条件与实验记录保留。

用户评分（1～5）：看得清、查得明、改得动、变化可信、值得继续观察。建议可接受目标为每项至少 4 分；这是人工评价，不可由助手自评代替用户反馈。即使规则全通过，用户无法辨认变化或不想继续观察，也应作为体验问题继续迭代。

## 8. P：建议性能与可靠性门槛

这些是待实测的工程目标，不是当前承诺。验收记录机器型号、内存、操作系统、浏览器版本、地图尺寸、物种配置、步长、日志级别、分辨率及后台模拟状态。

| ID | 场景 | 建议门槛 |
| --- | --- | --- |
| P01 | 标准 256×256，正常运行并平移缩放 60 秒 | 地图至少 30 FPS；点击到详情更新 p95 ≤200ms；不能用静止截图测帧率 |
| P02 | 最大加速中暂停／取消 | 输入到模拟停止 p95 ≤500ms；暂停后不继续消耗大量步数 |
| P03 | 标准地图直接生成 | ≤10 秒，期间有进度、可取消 |
| P04 | 标准配置推进 100 年 | ≤60 秒，报告实际步数和耗时；不能删掉种子、古树、矿化或小环境来通过 |
| P05 | 5 个登记种子各 500 年 | 不崩溃、无无效状态、通过 R 数值审计，输出每个种子的耗时与账差 |
| P06 | 连续运行 30 分钟并多次重新生成／载入 | 无遗留 worker、多重循环、持续无界日志和内存增长；报告内存曲线、上限与清理策略 |

至少在用户实际使用的桌面浏览器验收，并在另一种桌面浏览器做启动、绘制、编辑、保存继续的冒烟验证；未测试浏览器不得宣称支持。帧率、模拟吞吐和总内存分别报告。

若性能门槛未达，优先优化数据、批量更新、绘制及记录；若必须改变精度、规模或模型，明确列出影响再修订标准，不能静默缩小范围。

## 9. 交付证据与完成判定

必须交付：

- 可运行本地工程、依赖锁定与启动说明；不要求用户打开开发者工具才能操作。
- 当前规则与参数表：单位、输入来源、更新顺序、边界、限幅和所有暂定机制。
- 可用的种子配置、11 类受控实验初始数据及对照方案。
- R 自动检查与状态对比结果，S 实验指标和摘要，U 操作记录／截图或录屏，P 原始测量及汇总。
- 本地存档样本、版本信息、已知问题列表。

验收报告逐 ID 填写状态、证据路径、配置版本与失败原因。G 与 R 全通过、S 全覆盖且通过预设指标、U 完整可操作、P 有实测结论，才能宣布首版工程验收完成；用户体验评估另列“待用户评估／已评估”，不能以开发者检查冒充用户满意。

## 10. 尚未测定而需在实现中落实的工程选择

- 每格物理尺度、标准配置下时间步及 500 年对应步数。
- 地图外边缘的边界条件，不得改变州界语义。
- 同层替换的剩余个体去向、种子数量与库存更新、古树转记录的条件。
- 输入分配、失败转化、容量溢出、矿化及局部温湿度反馈的可调规则。
- 场景指标的具体阈值和观察窗口；先校准，再冻结并正式验收。

这些可通过小规模实验和参数校准完成，不必再次进行宽泛问卷；任何改变用户已定规则的选择都需明确提出。

## 实现期间用户补充（2026-09-16）

- UI 为可观测系统，地图优先；不用大字报、海报布局，按钮和面板让位于地图。
- 山川草木必须可辨认。州域应体现山河海的地理分界；划分依据自然通达性，州标签本身不额外改变自然流动。
- 地表灵气不能因缺失反馈而无区别持续铺满地图。高可用灵气需支持灵植积累、结构质变及更强承载，不能只提高地表浓度。这里不是要求强行总量平衡或无依据删除资源。
- **R21（新增）：**既有灵植在适配、实际积累和持续时间条件下可提高承载；增长不凭空新增库存，普通植物不自动转灵植。固定种子记录 0／20／40／60／80／100／500 年地表分位数、地下与生物库存、输入收支与阶段分布。与关闭质变的对照说明影响，不以单次视觉或缩小地图替代验证。
- 开发分步交付，可先提供基础版供随时介入；完整目标仍按本文件逐项验证，未测项目不标通过。

### R22 · 宇宙逸散与动态平衡

- 无输入的孤立游离灵气按有限速率衰减；被储存的库存不直接随之扣减。
- 各格与全局收支包含宇宙输出，数值损失不能隐瞒为误差。
- 稳定输入的受控环境应趋近输入与逸散相抵的状态；不要求自然世界每格恒定。
- 保存载入后累计逸散与后续演化可重现。旧场景和长期验收须按新规则重新验证。

### R23 · 浓度驱动吸收与竞争（用户补充）

- 其他条件相同，富集环境可使吸收更快，但不能超过源库存或承载；贫乏环境限制实际取用。
- 强吸收植物从共用库存扣减，草树不能重复取得同一份灵气；分层收支与全格收支相符。
- 质变不以六阶为世界内容上限，进一步提升仍需真实积累与持续时间。
- 对固定种子记录地表分位数、高值格占比、植物库存和阶段分布。观察阈值仅用于数值对比，不自动定义“灵地”或强制控制其数量。
