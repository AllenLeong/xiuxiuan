# 连续横版世界 · 当前定义与可玩切片

更新：2026-09-20。方向来源：用户本轮项目定义。下列“实现参数”是验证用工程选择，不等于正式世界规则。

## 当前决定

**世界模拟器 × 连续横版修仙 RPG × AI 叙事。**

- 宏观地图负责观察地理、生态、政治与历史；玩家在连续侧视空间实际活动。
- 同一空间同时包含地下、地表、山体、高空，能力改变通行方式，不按境界生成新地图。
- 局部实体按区块加载；远方生产、组织和历史不依赖玩家镜头。
- 建筑及遗迹由持久世界状态投影，组织灭亡不删除物理遗存。
- 原有 01 的自主历史原则、02 的灵气与生命规则继续有效。14 的俯视移动／飞行方案是历史建议；本文件替代其玩家空间方向。

月度时间为 10 个活跃页面秒；全局暂停停止时间。后台标签受浏览器调度限制，关闭网页不会自动补算现实经过的时间。“离屏演化”指同一运行模拟中，未加载的远处地点仍结算。

能力选择、观察定位、干预商路、闭关 20 年均为显式原型试验入口，不代表正式修炼、传送或时间规则。飞行尚未接入生态灵气账本。

### 横版空间的抽象规则【2026-09-20 已确定】

**参考图试作（最新）：** 玄岳山域已改成同一画面内的七块错层山地与谷地，包含林台、山腰院落、支峰、主峰。山体连续接到谷底，树林与建筑置于各处可站立表面。四条桥路、五条贴崖石阶连接这些地点；A/D 沿面行走，W/S 沿石阶上下，御器可跨越高度，V 切换全景和跟随近景。取消此前按 R 切换整条前后山剖面的交互。洞口 E 进入覆盖式内景。

原型用暴露在山体前侧的行走面表达纵深，可站立面和石阶实际影响移动；崖面的完整体积、人物被近山遮挡，以及前后路径的局部切换尚未做实体建模。岩壁画面不能等同于每一处均具有实体碰撞。当前验证重点是同屏多高度场所、通路与空间关系，暂不宣称完整三维地形。

本次先在玄岳验证；临河城和松崖门仍使用旧结构。新增测试验证全部石阶端点接地与双向通行、跨谷桥行走、跳跃落在上层、飞行；与既有横版测试合计 10 项通过。经济、归属和扩建状态继续驱动建筑，并保留在同一世界存档中。

横版的一条横轴不能误读为“所有活动都发生在同一条地面线上”。山体从山脚连续延伸到山顶，“层”表示同一山体上的活动高度，不能画成彼此分离的悬空土地。山林、道路、村落、楼台、城墙与洞口沿山势展开；角色横向穿行代表绕过山的前后侧，山体在身后延续。

实现中，连续山体轮廓负责山体的外观和接地关系；可走表面负责各高度路线的碰撞。山体背景不直接作为挡住所有横向行走的实心墙，只有明确洞口才切换洞内场景。当前保留简化的台地路线与楼梯，尚未生成完整纵深路网。

| 空间层 | 典型内容 | 主要通行方式 |
|---|---|---|
| 第一层地基 | 村落、城门、山麓森林、山坡 | 步行、车马、低境界活动 |
| 山门地基 | 城楼、山门、低山、林院、洞口 | 山坡、石阶、楼梯 |
| 云下地基 | 支峰、林地、院落、洞府 | 山坡、楼梯、御器 |
| 云海地基 | 主峰、古林、高阶宗门建筑与洞府 | 险坡、楼梯、御器、御剑 |
| 天外层 | 浮空岛及未来高空区域 | 高阶飞行 |
| 地下／地脉 | 矿井、天然洞穴、遗迹 | 固定入口、矿井梯道 |

玩家走进山的范围时，首先进入山林地表，而非自动进入山腹隧道。每层地基内部都可横向行走，山体斜坡本身也可步行；多处楼梯则提供更直接的层间通道。山洞是附着在某一层地基或山体上的明确入口，进入后切换为覆盖外景的洞内空间，再从入口返回原层。除这些洞穴、矿井与遗迹外，地基不可自由挖掘。

城镇与宗门也不是单层布点。城镇具有城墙、街道、城楼和内城高层；宗门具有山门、山坡、楼梯、支峰和主峰。当前原型已经用分层地基、每层独立山体、连续坡道、多处楼梯、层上树林与建筑表达这一结构；几何仍为验证用简化形态。

### 最小因果链

矿藏 → 月产出 → 矿场库存 → 商路运输 → 城市库存 → 消费；流量改变矿主收入，经费与人口决定扩建、失守、解散。商路通畅和中断会出现不同结果，并非到达指定年份直接触发灭宗。

矿石核算：地下剩余 + 矿场库存 + 城市库存 + 玩家持有 + 已消耗 = 初始总量（6065）。交易为转移，捐赠进入消耗池。经费使用简化外部收入，不宣称是全世界闭合经济。

| 验收 | 证据与状态 |

| 地表、竖井、矿道、遗迹、深层可连通 | 爬梯往返及可通行区域连通检查；测试通过 |
| 飞行用同一套空间与碰撞 | 升降、能耗、耗尽坠落、地面恢复；测试通过 |
| 境界活动范围不在同一水平线 | 主峰高程低于 −5000；宗门有五级以上地基，每层有山体，多条坡道和楼梯相连；测试通过 |
| 洞穴属于各层并覆盖外景 | 洞口分布在至少三种高度层；进入后使用独立洞内画面与移动范围，再由同一入口退出；测试通过 |
| 普通地基不可随意挖掘 | 村落地基拒绝开凿，已发现矿层允许开采；测试通过 |
| 卸载不丢挖掘状态 | 超出缓存后重入、序列化再载入；测试通过 |
| 镜头之外照常演化 | 20 年两种商路条件对照，验证所有权、扩建、遗址及资源守恒；测试通过 |
| 实际浏览器可操作 | 验证客舍交互、观察定位、地下及高空实体、世界记录；见本次交付说明 |

## 后续接入契约

1. 统一 `WorldState` 拥有全局地点、组织、人物和资源 ID；宏观地图与侧视图读取同一份权威状态。
2. 宏观地域下包含多个侧视区段，每段记录所属地域、面积权重、地质剖面和出入口。二维宏观世界不能无损压成一条横轴；区域之间的通路拓扑需要单独设计。
3. 局部模拟只细化已分配的物质预算；挖掘、采收、死亡、建造产生带时间和地点的事件，提交全局校验，避免大小地图重复生产。
4. 区块卸载保存差异与事件，不能把它重置为最初生成状态；重新加载先应用全局最新历史，再应用局部差异。
5. 生态状态决定地表、植被和风险；组织状态决定建筑、标识与人口。加载场景不应反过来生成尚无历史来源的组织。
6. AI 只读角色知情范围并表达；承诺、交易和动作仍由世界程序校验。

当前项目定义
一个拥有自主历史演化的连续横版修仙世界。
后台运行地理、资源、人物、宗门、经济、政治、战争与历史；玩家作为世界中的普通人物出生，在类似《泰拉瑞亚》的连续侧视空间中生活、探索、修炼和参与历史。
世界模拟器 × 横版修仙 RPG × AI 叙事。

它已经不是“类似《鬼谷八荒》的大地图游戏”这么简单了。

一句话版本
做一个像《泰拉瑞亚》一样真正连续、可行走、可飞行、可上下探索的巨大横版修仙世界，但这个世界里的城市、宗门、人物、经济、政治和战争会自己运行数百年；玩家不是世界中心，而只是出生在其中的一个普通人，最终可能通过自己的一生改变历史。

我觉得我们现在已经把“这个游戏到底长什么样”这件事情基本找到答案了。
接下来最值得停止画概念图、开始真正设计的是：一块可玩的连续原型地图——只做约 15–30 分钟横向旅行范围，但必须同时包含一座凡人城市、一个小宗门、一座大型仙门、村庄、河流、山体、矿洞、地下遗迹和高空区域，并让玩家真的可以从地下走到地表、从城市走到山门、最后一路爬/飞到主峰。这个 Vertical Slice 如果成立，整个游戏的空间方案基本就成立了。
